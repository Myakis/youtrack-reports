# TrackDesk

Расширение браузера для отчётности по задачам YouTrack (`youtrack.office.lan`): выбираете исполнителя —
получаете все его задачи в статусе «Готово» за период и выгружаете их с описанием, тегами, досками и комментариями,
чтобы загрузить в модель для сводки. Работает через вашу сессию YouTrack в браузере.

## Установка

Готовые пакеты — на странице [Releases](https://github.com/Myakis/youtrack-reports/releases/latest).

**Chrome / Edge / Яндекс Браузер:** распакуйте `TrackDesk-<версия>-chromium.zip` в постоянную папку →
`chrome://extensions` → «Режим разработчика» → «Загрузить распакованное расширение».
Новая версия — распакуйте поверх той же папки и нажмите ⟳ у TrackDesk (без ⟳ Chrome останется на старой версии).

**Firefox (Developer Edition):** один раз `about:config` → `xpinstall.signatures.required` = `false`; затем перетащите
`TrackDesk-<версия>-firefox.xpi` в окно Firefox. При первом запуске разрешите доступ к `youtrack.office.lan`.

## Как пользоваться

1. Нажмите значок TrackDesk — откроется вкладка.
2. **Исполнитель** — начните вводить имя или логин, выберите из списка. ☆ — добавить человека в «Команду»:
   дальше выбирать его можно одним щелчком (и сразу запускается поиск).
   Режим **исполнитель / участник**: «участник» находит и задачи, которые сотрудник делал, а закрыл другой
   (тестировщик) — по истории поля «Исполнитель» у каждой задачи фильтра, как скрипт YoutrackReportByUser.
   Галочка «+ менял / комментировал» — ещё задачи, где он менял поля или комментировал. Колонка «Участие» — как именно.
3. **Статус** — по умолчанию «Готово»; можно несколько через запятую («Ревью, Готово» — любой из них).
   **Проект**, **Тип** («Frontend, Mobile»), **Тег** («CashDash») — необязательно.
4. **Период** — этот / прошлый месяц, квартал, год, свой; «по дате» — решения, обновления или создания задачи.
5. «Найти» (Enter). Галочка **Доски** — определить доски и спринты задач (дольше на больших досках).
6. Щелчок по задаче — справа поля, описание и комментарии; двойной щелчок — открыть в YouTrack.
   Фильтр над таблицей сужает найденное; снимите галочку у задачи, чтобы не выгружать её.
7. **Выгрузить…** (Ctrl+S) — Markdown (лучше всего для модели), JSON, CSV для Excel или TXT как в скрипте; можно отключить описание,
   комментарии, поля и добавить инструкцию для модели. **✦ Для ИИ** — открыть чат с моделью chat.office.lan
   (вкладка «✦ ИИ» справа): отмеченные задачи и инструкция для отчёта уже подставлены — поправьте и «Отправить».
   Нужен вход в chat.office.lan, как для ИИ в LogDesk.
8. «Запрос YouTrack» — итоговый запрос на языке поиска YouTrack; его можно поправить вручную (`↺ Из полей` — вернуть).

## Вход

TrackDesk сначала использует сессию браузера. Если YouTrack не пускает (бывает, когда API требует токен):
YouTrack → профиль → «Безопасность аккаунта» → «Новый токен» (область YouTrack) → вставьте в «Настройки».
Токен хранится только в хранилище расширения в этом браузере.

## Как это устроено

- `src/core/youtrack.ts` — REST API YouTrack: `/api/issues` страницами по 100, пользователи, проекты.
  Запрос: `assignee: {логин} state: {Ревью}, {Готово} type: {…} tag: {…} resolved date: …`.
- Доски: в REST у задачи нет поля «доска», поэтому берутся доски (`/api/agiles`) проектов найденных задач
  и состав их спринтов. Доска без спринтов подписывается просто названием, со спринтами — «Доска / Спринт».
- `src/core/participation.ts` — поиск по участию: история поля «Исполнитель» у каждой задачи фильтра (до 3 000 задач).
- `src/core/export.ts` — Markdown / JSON / CSV / TXT; `src/core/prompts.ts` — запросы к модели; `src/app/ai.ts` — чат.

## Для разработки

Нужен Node.js 22 или новее.

```
npm ci
npm run typecheck
npm test
npm run build        # dist/firefox, dist/chromium и пакеты в release/
npm run icons        # пересоздать иконки
```

Для разработки в Chrome удобно загрузить распакованное расширение прямо из `dist/chromium`: после `npm run build`
достаточно нажать ⟳ у TrackDesk на `chrome://extensions`.

Страницу можно открыть без расширения на тестовых данных: `python3 -m http.server 8778` из папки проекта →
`http://localhost:8778/dist/firefox/app.html`.

## Релиз

Пайплайны GitHub Actions (`.github/workflows/`):

- **CI** — на каждый пуш в `main` и пул-реквест: типы, тесты, сборка; пакеты лежат в артефактах запуска 14 дней.
- **Release** — проверка, сборка и [GitHub Release](https://github.com/Myakis/youtrack-reports/releases) с пакетами
  для Chrome и Firefox. Описание релиза — раздел этой версии из `CHANGELOG.md`.

Как выпустить версию:

1. Поднимите `version` в `package.json` и добавьте сверху `CHANGELOG.md` раздел `## X.Y.Z — ДД.ММ.ГГГГ`.
2. Закоммитьте и отправьте в `main`.
3. Запустите релиз — любым способом:
   - тегом: `git tag vX.Y.Z && git push origin vX.Y.Z` (тег должен совпадать с версией в `package.json`);
   - кнопкой: GitHub → Actions → Release → Run workflow (тег создастся сам из версии в `package.json`).

Релиз не соберётся, если тег не совпадает с версией, такой релиз уже есть или в `CHANGELOG.md` нет раздела версии.
